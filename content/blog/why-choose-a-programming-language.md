# Why is it Important to Know?

So far for every single interview I've had, it has been among the first questions that I've been asked. The first time I was asked I drew a blank completely and it set the tone for the rest of the interview in a not-so-good kind of way. It felt like a question that I could only answer in the abstract, but when trying to come up with concrete examples, the only answer I could come up with was how in school you'd typically get thought the one that was the most relevant to what you were learning. When learning low level programming basics, the teacher would pick assembly, then as you'd go higher you'd move to Java or C++. Then near the end of your schooling, when concepts became more important than implementation, you'd go with something like Python for its low learning curve. With how prevalent AI is becoming and how intrusive it is in coding, it wouldn't be surprising if this knowledge isn't even relevant anymore. Now to Answer the question, in the most basic way, you need to know which language helps you most solve the problem you are trying to solve.

## Why Pick One Over the Other?

When you are building, you have to consider what it is you're trying to achieve and how. Because each language is better suited for particular kinds of projects, it is a good idea to know which one does better than the other. 
To give some concrete examples (which I was unable to do the first time I interviewed):

-JavaScript / TypeScript → websites and web applications
-Python → data analysis, automation, AI/ML, scripting
-Java → large enterprise applications, Android legacy systems
-C# → .NET applications, enterprise software, game development with Unity
-C/C++ → operating systems, embedded systems, high-performance software
-Go → backend services, networking, cloud infrastructure
-Rust → systems programming where performance and memory safety matter

There's more to it of course, but the specific details are best left as an internet search exercise. Other important factors include performance, scalability, and predictability.

## The Human Side of the Matter

Now outside of the technical aspects, there are other things to consider as well. If you are working with other people, you want to consider how many of the people working with you already know the language. And if some of them don't, then how easy would it be for them to pick it up on the fly? Additionally some languages have a lot of topic-specific libraries, like Python and data analysis. This means that a lot of work has already been done for you and you do not need to reinvent the wheel. For some, it also matters how many job opportunities are available (or will be) in a certain programming language. For those who want to stay in the same field, or even workplace, it is also important to consider how easy it is to maintain. It is nice when you go back to something from years ago and you can make additions and fixes quite easily


## What's Next?

The Computer Science ecosystem already has a reputation for changing pretty quickly. And the changes have only become more common with the advances in AI. So it is important to keep up with a high level understanding of topics even if the more specific details change rapidly. Just a year or two ago it was a common saying between my friend group that you could consider yourself knowledgeable on a topic if you could spot mistakes that LLMs were making. But can we really say that is true now or if if it will be true a couple years or even months from now?
